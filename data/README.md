# Данные HW2

Рабочий источник: официальный портал ИТМО, справочная информация о поступлении на бакалавриат. Снимок получен 11 ноября 2026 года. Сбор не является интеграцией с университетом; содержимое меняется независимо от репозитория.

## Что хранится в Git

- `sources/registry.csv` — фиксированный список 59 кандидатов с темой, уровнем, предварительной областью действия и parent URL. Это реестр сбора, не список 59 успешно полученных документов.
- `sources/discovery.csv` — 82 проверенных адреса разведки и решение об отборе. Сами исключённые страницы в рабочий индекс не включаются.
- `sources/review.csv` — четыре исправления/решения после чтения содержимого: три карантина сроков и один смешанный уровень. Проверка привязана к SHA-256, offsets — по очищенному тексту.
- `evaluation/` — открытые модельные вопросы разработки и правила их проверки.
- `../reports/data/20261111_itmo_bachelor_reviewed_v2/` — итоговые диагностические таблицы без полных текстов. Предыдущие варианты сохранены как история обработки, для отчёта используется v2.
- `../reports/provenance/` — журнал сбора, robots.txt, версии и контрольные суммы.

Исходный HTML и полный извлечённый текст не опубликованы: право на перепубликацию всего корпуса не подтверждено; в страницах есть публичные контакты людей. Ссылки на источники не заменяют проверку условий использования. Они предназначены для воспроизведения локальной исследовательской работы.

## Локальные артефакты (игнорируются Git)

- `raw/20261111_discovery_v2/` — исходная разведка;
- `raw/20261111_itmo_bachelor_v1/` — рабочий сбор: хешированные HTML, `documents.jsonl`, robots, sitemap, журнал запросов и окружение;
- `processed/20261111_itmo_bachelor_reviewed_v2/` — документы и фрагменты с полным текстом;
- промежуточные снимки сохранены, не перезаписываются.

Идентификатор источника — первые 16 hex-символов SHA-256 канонического URL. Это не идентификатор версии. Версию задаёт полный SHA-256 HTTP-тела. `text_sha256` относится к UTF-8 очищенного текста. У каждого фрагмента есть URL, source ID, страница для PDF (для HTML 0), границы `[start,end)` в тексте и свой хеш. В текущем корпусе PDF нет.

Год в `campaign_year` — предварительно подтверждённый на уровне документа, пустое значение означает отсутствие такой проверки. `year_mentions` перечисляет любые найденные годы, включая исторические. Значение `undated` не означает доказанное устаревание. `retrieval_eligible` — допуск к офлайн-эксперименту, не допуск к автоматическому ответу пользователю.

## Воспроизведение

```bash
uv sync --group eda --locked
make test
make eda
make notebook
```

Эти команды используют публичные диагностические CSV, не скачивают корпус и не обращаются к LLM. Ноутбук выполняется интерпретатором проекта в временном Jupyter kernel, глобальная конфигурация пользователя не меняется.

Для нового сбора:

```bash
uv run --group eda python scripts/collect_corpus.py \
  --registry data/sources/registry.csv --run-id NEW_RAW_ID
```

Идентификатор должен быть новым. Сборщик откажется записывать в существующий каталог. Старые результаты не удаляются. Сетевые ошибки и запреты обхода остаются отдельными записями; повтор не скрывает исходный неуспех. Если файл или robots.txt изменились, результат закономерно отличается от исходного отчёта.

Для точного повторения подготовки на **локально сохранённом** исходном снимке:

```bash
uv run --group eda python scripts/prepare_corpus.py \
  --snapshot data/raw/20261111_itmo_bachelor_v1 \
  --review data/sources/review.csv --output-id NEW_DERIVED_ID
uv run --group eda python scripts/run_eda.py --snapshot NEW_DERIVED_ID
uv run --group eda python scripts/evaluate_bm25.py \
  --snapshot NEW_DERIVED_ID --output-id NEW_BASELINE_ID
```

В новом скачанном снимке сначала проверить `review.csv` и разметку вопросов: они привязаны к старым хешам. Не отключать проверку совпадения ради запуска. Для оценки на исходном рабочем снимке можно использовать `make baseline BASELINE_RUN=NEW_BASELINE_ID`.

Отчёт строится на v2, где исправлена разметка `/page/86`. Объём текста и индекс между reviewed_v1 и reviewed_v2 одинаковы; результаты первого BM25-прогона сохранены отдельно. Сетевой сбор выполнялся Python 3.11.0 из прежнего окружения Anaconda. Проверки и ноутбук выполняются на uv-managed Python 3.11.15: в прежнем окружении импорт `readline` приводил к segmentation fault pytest. Это смена среды проверки, не повторный сбор данных.
