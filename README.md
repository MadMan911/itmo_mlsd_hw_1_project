# UniAssist — LLM-агент поддержки студентов и абитуриентов

Проект курса **ML System Design** (ИТМО).

UniAssist — проект ассистента в Telegram. Целевое поведение: он отвечает на вопросы абитуриентов и студентов по официальным документам вуза: правилам приёма, положениям, расписаниям, FAQ. Каждый ответ сопровождается ссылкой на источник, а если ассистент не уверен в ответе, он передаёт вопрос оператору.

## Проблема

Приёмная комиссия и учебные офисы получают поток однотипных вопросов, особенно в приёмную кампанию: сроки, документы, проходные баллы, перевод, академический отпуск. Ответа приходится ждать часами, операторы перегружены, а нужная информация разбросана по десяткам страниц и PDF.

## Решение

- **RAG** по базе знаний из публичных источников вуза: гибридный поиск (BM25 + эмбеддинги) и reranker.
- **LLM-агент**: классифицирует интент, переформулирует запрос с учётом истории, генерирует ответ с цитатами.
- **Механизм уверенности**: если уверенность низкая, тема чувствительная или пользователь просит позвать человека, обращение передаётся оператору вместе с резюме диалога.
- **Guardrails**: маскирование персональных данных, защита от prompt injection и офтопика.

## Ключевые метрики

| Бизнес | ML |
|---|---|
| Automation rate (доля обращений, закрытых без оператора) | Recall@5 поиска |
| CSAT | Answer correctness, faithfulness |
| Время первого ответа | Precision ответов / coverage при эскалации |
| Нагрузка на операторов | p95 латентность, стоимость за обращение |

## Что сделано в HW2

Выбрана справочная поддержка абитуриентов **бакалавриата ИТМО**. Собран снимок 44 официальных HTML-страниц кампании 2026, около 93 тыс. слов. Найдены шаблонные повторы, смешение уровней образования, три страницы со старыми сроками и неполная таблица мест. В поисковый эксперимент включены 40 документов / 576 фрагментов после карантина.

Есть 36 открытых модельных случаев разработки. BM25 на 24 вопросах с подтверждением даёт Evidence Hit@5 = 0,50. Это диагностика поиска, не независимая оценка RAG. Реальные обращения, закрытый test, генерация, бот и пилот пока отсутствуют. 15 PDF закрыты для автоматического обхода; их содержимое не исследовано. Корпус 2026 не подтверждает правила кампании 2027.

## Структура репозитория

```
├── data/sources/            # URL, решения отбора и проверки источников
├── data/evaluation/         # открытые вопросы разработки и инструкция разметки
├── docs/                    # дизайн-документ и чеклист HW2
├── notebooks/               # выполненный EDA
├── reports/                 # отчёты, графики, диагностические CSV и прогоны BM25
├── scripts/                 # сбор, подготовка, EDA, выполнение ноутбука и оценка
├── src/app/                 # общие функции обработки корпуса; каркас сервиса
├── tests/                   # тесты парсинга, границ фрагментов и контрактов данных
├── .github/workflows/       # CI: pre-commit и pytest
└── Makefile                 # команды воспроизведения
```

Полные HTML и тексты лежат локально в `data/raw/` и `data/processed/`, игнорируются Git. Исходные снимки не перезаписываются. Публичные отчёты и графики воспроизводятся из диагностических CSV без загрузки корпуса.

## Разработка

Нужен [uv](https://docs.astral.sh/uv/).

```bash
make install   # установка зависимостей и pre-commit хуков
make lint      # ruff check + ruff format --check + mypy
make format    # автоисправление и форматирование
make test      # pytest
make eda       # графики и агрегаты из CSV, без сети
make notebook  # выполнить ноутбук в окружении проекта
# BM25 требует локально сохранённых текстов:
make baseline BASELINE_RUN=my_new_run
```

Хуки pre-commit (ruff, ruff-format, mypy, базовые проверки файлов) запускаются при каждом коммите и в CI на каждый PR.
